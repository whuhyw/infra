# Product Design

## 概述

InformationProvider 是武汉大学校园电费信息查询系统的中间层服务。它对接学校供电系统的 HTTP API，将数据缓存在本地数据库，对外提供稳定的 HTTP API 供 QQ 机器人使用。

## 用户角色

| 角色 | 说明 |
|------|------|
| **学生** | 最终用户，通过 QQ 机器人与系统交互。查询宿舍电费余额、日用电量、用电趋势。 |
| **QQ 机器人维护者** | 运维人员，负责 QQ 机器人的开发和维护。调用 InformationProvider API 获取数据。 |
| **系统管理员** | 负责 InformationProvider 的部署、配置和监控。 |

## 用户旅程

### 首次使用

```
1. 学生发 QQ 消息: "订阅 枫园14舍-316"
2. QQ 机器人: "请问你的房间号是？"
3. 学生发: "314"
4. QQ 机器人调用 GET /api/areas → GET /api/areas/{id}/buildings → GET /api/buildings/{id}/rooms?floor=3
   （获取房间 ID 对应关系）
5. QQ 机器人调用 POST /api/rooms { "roomId": "123456" }
6. 系统回填所有历史数据（耗时数秒）
7. QQ 机器人: "订阅成功！当前余额: 50.75 元，昨日用电: 12.5 度"
```

### 日常查询

```
1. 学生发 QQ 消息: "查电费"
2. QQ 机器人调用 GET /api/rooms/{roomId}/balance
3. QQ 机器人: "房间 枫园14舍-316 当前余额: 48.50 元"
```

### 查看趋势

```
1. 学生发 QQ 消息: "近7天用电"
2. QQ 机器人调用 GET /api/rooms/{roomId}/trend?startDate=...&endDate=...
3. QQ 机器人渲染三合一趋势图并发送
4. QQ 机器人: "📊 近7天用电趋势（见图片）"
```

### 数据刷新

```
1. 学生觉得数据不对: "刷新"
2. QQ 机器人: "正在刷新数据..."
3. QQ 机器人调用 POST /api/rooms/{roomId}/refresh
4. QQ 机器人: "已更新！当前余额: 48.50 元，今日用电: 11.3 度"
```

## 非功能需求

- **响应时间**：99% 的查询请求在 200ms 内返回（仅读 DB）
- **数据延迟**：当天数据最晚在次日凌晨 2:00 后可用
- **可靠性**：定时任务失败后 15 分钟自动重试
- **并发**：最多同时 5 个房间的定时更新任务
- **存储**：SQLite 文件数据库，单文件部署
