# 0001 — Database as Source of Truth

数据库是本系统唯一的数据来源。WhuApi 仅在订阅回填和定时任务中被调用，所有用户查询（余额、日用量、趋势图）只读数据库。查询时若数据库查不到所属数据，视为数据不存在，而非触发 WhuApi 调用。

## Context

WHU 校园供电 API 有未公开的频率限制。如果每次用户查询都调用 WhuApi，一是不稳定（可能被限频），二是会给学校服务器造成不必要的负担。

## Decision

引入 SQLite 本地数据库，作为用户查询的唯一数据来源。WhuApi 只在两个受控的场景中被调用：

1. **订阅回填** — 用户在 QQ bot 中首次订阅房间时，从 WhuApi 回溯该房间所有历史日用电量数据并写入数据库。
2. **定时任务** — 每天凌晨定时器遍历所有已订阅房间，从 WhuApi 拉取前一天的数据（用电量、电量金额、余额）并写入数据库。

两个受控场景之外的任何 API 调用都不应发生。用户请求若数据库中无对应数据，直接返回"无数据"，不尝试活体调用 WhuApi。

## Consequences

- 用户可能需要等待定时任务执行后才能看到最新数据（而不是每次查询都实时）。可以接受，因为电费数据是 T+1 更新的，本身不存在实时强需求。
- 定时任务成为系统的关键路径，必须设计好重试和告警机制。
- 首次订阅时回填所有历史数据可能需要一段时间（取决于历史天数 + WHU API 响应速度），订阅 API 可能需要异步返回。
